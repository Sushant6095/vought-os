# Wave 5 · /contact

## What was done

Built `apps/web/app/contact/page.tsx` per VOUGHT-DESIGN-BLUEPRINT.md §11. Deliberately short single-screen page. No long contact form — three cards, three options, one office block, one security note.

## Sections shipped

1. **Hero** — eyebrow `Contact` + `display-3xl` headline *"How can we help?"* No subhead.
2. **Three-card grid** (1×3 desktop, single column mobile):
   - **Book a demo** — flagship variant. Amber-edged border + `Primary` tag, three trust bullets, `pill-cta` amber pill CTA → `/demo`.
   - **Email sales** — standard variant. `sales@vought.com` as `mailto:` link with `ArrowRight` chevron-grow hover.
   - **Email support** — standard variant. `support@vought.com` as `mailto:` link, mirrors sales card shape.
3. **Office block** — 12-col split. Left: SF address (`<address>`, semantic). Right: *"We respond to every email within 24 hours. We do not auto-reply with chatbots."*
4. **Security note** — single-line footer-above-footer linking `/security`.

## Reuse decisions

- Pulled the **PillarCards flagship + standard variant** styling directly (matching borders, gradient background, amber accent, `Check` bullets, `delayMs` stagger). The contact cards visually rhyme with the product pillars on the landing page — same vocabulary.
- Pulled the **hero pattern** from Hero.tsx (label-small amber eyebrow + display-3xl headline + reveal motion stagger 80ms / 240ms).
- Pulled the **pill-cta + mailto link arrow-grow** treatment from CTAStrip + PillarCards.
- No need to import Footer — it's already mounted in the root layout.
- No need to import NavPill — same reason.

## Brand voice compliance

- All sentences declarative. No hedging, no "AI-powered," no "supercharge."
- 24-hour promise stated as a fact, not a marketing claim.
- Single accent (amber) used only on the primary card and pill.
- No numbers on this page — the specificity comes from the 24-hour promise + the named office + the explicit anti-chatbot pledge. That is the right tradeoff for a contact surface; latency metrics belong elsewhere.

## Motion compliance

- All section reveals use the global `.reveal` IntersectionObserver hook.
- All hover transitions use `duration-quick ease-quick` tokens — no raw values.
- Stagger delays: 0 / 80 / 240ms — within canonical motion tokens.

## Accessibility

- `<address>` element for the SF location.
- `aria-labelledby` on hero, `aria-label` on every other section.
- `<h1>` for the page title, `<h2>` for each card title — single hierarchy.
- Mailto links have full visible address text — no hidden labels.

## Scope kept

- Only `apps/web/app/contact/page.tsx` touched.
- No edits to packages/, services/, apps/app/, or existing marketing components.
- Nav already lists `/contact` in the Footer (Company column) — verified, no change needed.

## Type check

`npx tsc --noEmit` reports only pre-existing errors in `packages/ui/src/primitives/*` and `packages/design-system/tailwind.config.ts`. No errors in the contact page.
