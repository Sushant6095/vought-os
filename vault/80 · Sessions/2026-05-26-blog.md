Blueprint §11 long-form template. No `/blog/[slug]` detail pages this
wave — every card href is `#` per the brief.

### Files

No other files were touched. Nav already links to `/blog` (verified in
`components/marketing/Footer.tsx:52`).

## Sections (top → bottom)

1. **BlogHero** — eyebrow *"The Vought blog"* in `text-accent-amber` +
   headline *"Notes from the conversation."* in `display-2xl`. Matches
   the customers-page tiny-header pattern (eyebrow → headline → sub),
   same 80/240ms reveal stagger as Hero.
2. **CategoryRow** — five chips: All · Engineering · Customer stories ·
   Voice AI · Company. Anchored to `?cat=<slug>` via `<Link scroll={false}>`
   so the page stays a pure server component, filters are shareable, and
   no client JS is required. Active chip swaps to amber bg + ink text.
3. **FeaturedPostCard** — oversized 12-col card (image left 7-span /
   copy right 5-span at lg). Image is a gradient placeholder per the
   brief (no stock photography). Hidden when a category filter is
   active — featured is only meaningful on the unfiltered index.
4. **PostGrid** — 3-column grid (1 / 2 / 3 at sm / md / lg). Six cards
   when filter is "All". Each card: gradient thumbnail (44h), category
   eyebrow in amber, title, 30-word excerpt, author + date + reading-
   minute mono. Hover state shifts border `white/[0.08] → white/20` and
   scales the thumbnail `1.04` over 640ms cinematic ease.
5. **NewsletterBlock** — 7/5 split, headline *"One essay a month. No
   newsletter chaff."* + email input + Subscribe pill. `· 412 subscribers`
   in mono amber, brand callsign pattern. Form is declarative — no
   onSubmit toast confetti (Brand Voice §11).
6. **RSSNote** — *"Prefer your reader?" → "Subscribe via RSS"* anchored
   to `/blog/rss.xml`.

## Filtering approach

Filtering is server-side via `searchParams.cat`. Chip nav uses
`<Link href="/blog?cat=engineering" scroll={false}>`. The page reads
`searchParams.cat`, validates against the known category slug set, and
filters the post list before render. Benefits:

- Zero client-side JS for filtering — page stays a Server Component.
- Shareable filter URLs (`/blog?cat=engineering`).
- Empty-state copy when a category has no posts beyond the featured one.

## Brand-voice compliance

- Declarative sentences throughout. No "AI-powered". No "supercharge".
- Numbers in mono: `· 412ms`, `· 412 subscribers`, `· 12m read` — every
  numeric uses the brand-callsign amber-dot prefix + mono digits.
- No celebratory UI. Newsletter form submits to `#` (real handler is V2).
- No emojis in product UI.
- Named author + named customer everywhere — no anonymous bylines.

## Design-system compliance

- Colors via tokens only: `text-accent-amber`, `bg-accent-amber`,
  `bg-surface-dark`, `bg-marketing-ink`, `text-marketing-ink`,
  `text-live-emerald`, plus `text-white/[opacity]` and `border-white/[opacity]`.
- Spacing on the 4px grid: `gap-3`, `gap-6`, `gap-8`, `py-20`, `py-28`,
  `pt-40`, `pb-32`, etc.
- Motion timings via `duration-quick` (150ms) and `duration-cinematic`
  (640ms) — both registered in `packages/design-system/tailwind.config.ts`.
  No raw `transition: ... 240ms` anywhere.
- `.reveal` used for every section reveal; explicit `transitionDelay`
  staggers use the canonical 80 / 160 / 240 / 360ms scale.
- `Container` / `Grid` / `GridItem` primitives from `@vought/ui` reused
  exactly as the customers page and CTAStrip do.

## Responsive behavior

- 375 / 768: hero stacks single-column; chip row wraps; featured card
  stacks (image full-width, copy below); post grid is single column.
- 768–1024 (md): post grid is 2 columns.
- 1024+ (lg): featured card is 7/5 split horizontally; post grid is
  3 columns. Newsletter is 7/5 split.
- 1440+: capped by `Container width="marketing"` (matches landing).
